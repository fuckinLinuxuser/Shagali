# Чек-лист релиза на reg.ru (то, что делается на сервере руками)

Код выкатывается сам: пуш в `main` → GitHub Actions → rsync. Всё ниже — одноразовая настройка сервера, которую CI сделать не может.
Порядок важен: сначала БД и конфиг, потом открывать функции.

## 0. Сайт включён?
Если прод отвечает страницей «Работа сайта приостановлена» — услуга не оплачена или сайт отключён в панели reg.ru. Включить.
Проверка: `npm run smoke -- https://shagali.ru` (из `astro/`) — должно быть «проблем 0».

## 1. База данных
1. В панели reg.ru создать MySQL-базу и пользователя; записать имя, пользователя, пароль (в чат и в репозиторий не писать).
2. Применить миграции по порядку через phpMyAdmin (вкладка «Импорт» или SQL): `sql/001_init.sql`, `sql/002_users.sql`, `sql/003_agent_codes.sql`.
   Каждая сама записывает себя в `schema_migrations`.

## 2. Серверный конфиг `/var/www/u3413841/data/shagali-config.php` (вне корня сайта)
Шаблон — `shagali-config.example.php` в корне репозитория. Ключи:

| Ключ | Что это |
|---|---|
| `admin_password_hash` | хеш пароля админки (`php -r 'echo password_hash(trim(fgets(STDIN)), PASSWORD_DEFAULT);'`) |
| `gate_password_hash` | хеш пароля входа на закрытый сайт (заглушка), см. `docs/SITE-PASSWORD.md` |
| `db` | `['dsn' => 'mysql:host=localhost;dbname=ИМЯ;charset=utf8mb4', 'user' => …, 'pass' => …]` |
| `rate_salt` | любая длинная случайная строка (соль для хешей IP/почты в лимитах) |
| `site_url` | `https://shagali.ru` (ссылки в письмах) |
| `mail_from` | отправитель писем, например `no-reply@shagali.ru` |
| `notify_email` | куда слать заявки с форм (адрес заказчика) |
| `promo_codes` | `['12' => 'КОД']` — промокод 12% (значение от заказчика) |
| `backstage_dir` | папка закулисья вне `www/`, например `/var/www/u3413841/data/backstage` |
| `backup_dir` | папка бэкапов вне `www/`, например `/var/www/u3413841/data/backups` |

## 3. Бэкапы
Cron в панели reg.ru — см. `docs/BACKUP.md`. Один раз запустить вручную и проверить, что файл появился.

## 4. Проверки после выкладки
- `npm run smoke -- https://shagali.ru` — зелёный.
- Окно инкогнито: заглушка «Сайт в разработке»; «войдите» → пароль → сайт (`/preview`).
- Реальная заявка в лист ожидания с телефона → письмо приходит на `notify_email` (доставку `mail()` можно проверить только на проде).
- Регистрация в `/lk/register` → письмо со ссылкой → вход (то же про `mail()`; если письма не приходят или попадают в спам — нужны SPF/DKIM домена).
- В Метрике (счётчик 114626453) в течение суток видны визиты и цели `city_view`, `buy_click`, `widget_loaded`, `purchase`, `waitlist_submit`, `feedback_submit` (после «Принять» в cookie-плашке).

## 5. Запуск витрины (3 декабря)
В `astro/src/data/site.json` поставить `"closed": false`, пока не заполнены юридические страницы — нельзя: `check:content` не пропустит
`TODO(контент)` в `/privacy` и `/consent` (нужны юридический адрес, дата редакции и тексты, см. `astro/src/data/operator.json`). Ссылки на `/lk` в меню сайта не добавлены —
кабинет открывается по адресу `/lk/login`, когда решите его анонсировать.

## Ограничения хостинга, которые мы выяснили
- Перед сайтом стоит nginx, `.htaccess` не применяется: пароль на весь домен и правила закрытия файлов из репозитория не работают.
  Заглушка — маскировка (страницы по прямым адресам открываются). Настоящая защита — только настройками хостинга.
- Редирект `/путь` → `/путь/` делает сервер (лишний запрос); убрать можно настройкой хостинга.
