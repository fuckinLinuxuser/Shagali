# Закрытый просмотр прода: заглушка «Сайт в разработке» и вход по паролю

Хостинг reg.ru отдаёт сайт через nginx, и `.htaccess` там **не применяется** — защита паролем на весь домен из репозитория невозможна.
Поэтому сделана заглушка:

- Пока `astro/src/data/site.json` → `"closed": true`, на `/` стоит страница «Сайт в разработке» (`ComingSoon.astro`), настоящая главная лежит на `/preview`,
  все страницы получают `noindex`. На заглушке нет счётчиков и cookie-плашки.
- Слово «войдите» открывает окно пароля. Пароль проверяет `/api/gate.php` (`password_verify` по хешу из серверного конфига).
  Верный пароль ставит cookie `shagali_preview=1` и ведёт на `/preview`; при следующем заходе на `/` заглушка сразу перекидывает на `/preview`.
- 10 неверных попыток за 10 минут с одного IP → 429.

## Ограничение — это маскировка, а не замок

Страницы сайта — статические файлы, их отдаёт nginx без участия PHP. Кто знает адрес (`/goroda`, `/spasibo`, `/preview` и т. д.),
откроет его без пароля; `noindex` лишь убирает их из поиска. Настоящая защита — только на уровне хостинга (панель reg.ru или поддержка:
«включить HTTP Basic Auth на весь домен для nginx»). Когда она появится, заглушка не понадобится.

## Как задать пароль на сервере (один раз)

1. Сделать хеш у себя (пароль вводится в терминале, не в чате и не в репозитории):
   ```bash
   php -r 'echo password_hash(trim(fgets(STDIN)), PASSWORD_DEFAULT), "\n";'
   ```
2. В `/var/www/u3413841/data/shagali-config.php` добавить ключ `'gate_password_hash' => '<хеш>'` (шаблон — `shagali-config.example.php`).
   Нет ключа → вход отвечает 503, на сайт не попасть.

## Как открыть сайт к запуску

В `astro/src/data/site.json` поставить `"closed": false` (PR в `main`). Заглушка исчезнет, `/preview` начнёт перенаправлять на `/`, `noindex` пропадёт.
Файлы `ComingSoon.astro`, `zastavka.astro`, `gate.php` можно удалить позже.
