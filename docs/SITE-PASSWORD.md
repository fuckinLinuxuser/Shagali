# Пароль на весь домен (закрытый просмотр прода)

Защита — HTTP Basic Auth из `astro/public/.htaccess` (блок в самом начале файла). Пароль в репозитории не хранится:
хеш лежит в файле `.htpasswd` на сервере вне корня сайта.

## Как включить (один раз, на сервере)

Путь файла: `/var/www/u3413841/data/.htpasswd` (рядом с `shagali-config.php`, не в `www/`).

По SSH (пароль спросит интерактивно, в историю команд он не попадёт):

```bash
htpasswd -cB /var/www/u3413841/data/.htpasswd ИМЯ_ПОЛЬЗОВАТЕЛЯ
```

Если `htpasswd` на хостинге нет — хеш делается где угодно с PHP (пароль вводится в терминале, не в чате):

```bash
php -r 'echo "ИМЯ_ПОЛЬЗОВАТЕЛЯ:" . password_hash(trim(fgets(STDIN)), PASSWORD_BCRYPT) . "\n";' > htpasswd.txt
```

Содержимое `htpasswd.txt` положить в `/var/www/u3413841/data/.htpasswd` (права 644), локальный файл удалить.

Ещё один пользователь — та же команда без `-c`.

## Как проверить после деплоя

Открыть прод в **окне инкогнито** (в обычном браузере пароль может быть уже запомнен):
запрос логина = защита работает. Проверить и статику напрямую: `https://shagali.ru/robots.txt`, `https://shagali.ru/images/favicon.png`.
Если страница просит пароль, а картинки и css открываются без него — перед Apache стоит nginx, который отдаёт статику сам;
тогда пароль нужно включать в панели хостинга (защита каталога), а не здесь.

## Как работает

- Файл `.htpasswd` есть → пускает только по паролю (401 всем остальным, включая `/api/…` и `robots.txt`).
- Файла нет → **403 всем** (сайт не открывается случайно). Исключение: docker-стенд (`SHAGALI_STAND=1`) открыт без пароля.
- Метрика считает только тех, кто прошёл пароль (и принял cookie). Кнопка «Проверить код» в интерфейсе Метрики получит 401 — это нормально.

## Как открыть сайт к запуску

Удалить блок «Сайт закрыт паролем» из начала `astro/public/.htaccess` и задеплоить (отдельный PR). Файл `.htpasswd` можно удалить с сервера.
